# PR #5 最終候補・ミリシタ実機検証（2026-10-14）

## 結論

最終深度／ステンシルBlit修正をミリシタへ実際に読み込ませ、無料MVを4回完走した。今回確認した映像で新たなキャラの欠け・前後関係の乱れ・Diamond Jokerの白モヤ再発は見当たらない。独立GLES230件の結果と合わせ、このRX 9060 XTでの限定的な回帰確認は完了。PR #5の通常Mesa overlayへ検証した最終バイナリを反映してマージする。既存v0.84 Releaseは差し替えず、新しいReleaseも公開しない。

読み込み中の約500msはライブ描画の不具合・修正対象から外し、追加調査しない。以前のNative Bridgeクラッシュ1回は原因不明の参考記録として残し、この修正の不具合とは断定しない。最終候補を適用した今回の2回の起動と4回のMVではクラッシュを観測しなかった。全環境・長時間での無事故保証ではない。

## 次のVRAM Clock確認

この機体ではamdgpuの読み取りで実メモリコントローラクロックを取得可能。Thank You!歌唱40〜140秒では全サンプルが1,258MHz（freq2_input=1,258,000,000Hz）だった。自動クロックは既に最上位DPM状態を維持していた。実測値と製品のGDDR6データレートは単位が異なる。

1. 自動クロックの上がり方：100〜200ms間隔でメモリ／GPUクロック、負荷、消費電力、温度、実フレーム時間を記録し、同じ曲の引き・光源場面と重ねる。
2. 帯域側の詰まり確認：RTScale倍率を変えて同じ場面を比較し、メモリクロック一定でもGPU時間が伸びるか確認する。クロック値だけでメモリ帯域が原因とは判断しない。
3. クロックを上げた効果：別途ユーザーが選んだ場合に定格と小刻みな増分を比較し、FPS・フレーム時間・映像異常・ドライバエラー・安定性を確認する。現在の表示可能範囲は97〜1,500MHzだが、安定上限を意味しない。まだ設定変更・OC試験は行っていない。

仕様根拠：[Linux amdgpu公式文書](https://docs.kernel.org/gpu/amdgpu/thermal.html)。MWMへ汎用ハードウェア調整機能は追加しない。
